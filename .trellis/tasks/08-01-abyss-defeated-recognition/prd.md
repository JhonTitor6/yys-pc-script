# 修复狭间暗域已击破识别

## Goal

基于真实战报画面可靠识别头像上的红色“已击破”印章，跳过不可挑战目标，避免脚本重复选择已被击破的首领、副将或精英。

## Background

- `Main.get_next_enemy()` 当前只检查 `Enemy.has_challenged`，没有调用现有的 `_is_enemy_defeated()`。
- `_is_enemy_defeated()` 使用 OCR 查找“已击破”，但在真实夹具 `战报界面_已击破.png` 上以 `similarity_threshold=0.2` 实测，五个已击破目标均未识别出“已击破”。
- 真实画面中的“已击破”是覆盖在头像中央的大块红色印章，适合使用颜色连通区域判断。
- `战报界面_当前.png` 可作为负样本，`战报界面_已击破.png` 可作为正样本；两者客户区均为 1154×680。
- 新录制 `abyss_shadows_defeated_report/20260801T131829Z-ed1b57e9` 状态为 completed，客户区为 1136×640；事件 1 的稳定战报画面中，首领和两个副将已击破，三个精英未击破。
- 旧 `战报界面_已击破.png` 与新录制互为补充：旧图覆盖两个副将、三个精英的正样本和首领负样本，新图补齐首领正样本以及三个精英负样本。
- 新录制顶部含聊天内容，原始录制仅保留在 Git 忽略的 `recordings/`，不得直接提交；测试只使用经人工复核、不含聊天或账号信息的最小素材。
- 完整战斗录制 `abyss_shadows_full_battle/20260801T130608Z-bc28885d` 状态为 completed，包含副将伤害退出和首领胜利，但未捕获胜利后返回战报的稳定画面；该缺口不阻塞本任务的已击破识别。
- 当前工作区另有未提交的 `yys/douji/douji_script.py` 修改，不属于本任务。

## Requirements

- 对每个候选敌人的 `label_and_pic_position` 区域检测红色“已击破”印章。
- 检测逻辑必须使用相对尺寸、面积和形状约束，不能仅按红色像素数量判断，以降低红色角色立绘造成的误判。
- `get_next_enemy()` 必须跳过检测为已击破的目标，并将其 `has_challenged` 标记为 `True`，避免同一战报循环重复识别。
- 首领、副将、精英使用同一检测逻辑，不增加按敌人类型分叉的硬编码。
- 截图缓存缺失、裁剪为空或没有印章时必须安全返回 `False`。
- 当当前区域所有目标均已击破时，沿用现有切换区域流程；最后一个区域完成时必须安全停止，不能发生索引越界。
- 使用真实场景截图执行回归测试，不能只 Mock 检测结果。
- 回归样本必须同时覆盖 1154×680 和 1136×640，不依赖单一客户区绝对坐标或固定印章像素面积。
- 保留现有伤害限制、挑战次数和敌人优先级行为。

## Acceptance Criteria

- [ ] 在旧 `战报界面_已击破.png` 上，两个副将和三个精英均识别为已击破，未盖章首领识别为未击破。
- [ ] 在新 1136×640 最小素材上，首领和两个副将均识别为已击破，三个未盖章精英均识别为未击破。
- [ ] 在 `战报界面_当前.png` 上，首领、两个副将和三个精英均不误判为已击破。
- [ ] `get_next_enemy()` 会跳过已击破目标，并按首领 → 副将 → 精英顺序返回下一个可挑战目标。
- [ ] 当前区域所有目标均已击破时会切换到下一暗域并重置新区域内存状态。
- [ ] 最后一个暗域所有目标均已击破时脚本安全停止，不抛出 `IndexError`。
- [ ] 狭间暗域单元测试与场景回放测试通过。

## Out of Scope

- 不更换项目全局 OCR 后端。
- 不修改战斗伤害 OCR 与退出战斗逻辑。
- 不重新设计敌人优先级或挑战次数配置。
- 不处理不同客户区分辨率的整体界面缩放。
- 不在本任务内补齐“胜利结算 → 返回战报”的完整端到端回放；另行录制和建夹具。
