# GUI 现代化工作台总体设计

## 1. 设计目标

本次重构只重组 GUI 的信息架构、视觉系统和交互表达，不重写已经稳定的运行时。后端规范化快照、WebSocket 事件、配置 schema、工作流与历史接口继续作为事实来源；前端负责把这些事实转换为一致、可访问且适配 800×600 至大屏窗口的工作台界面。

## 2. 约束与依赖

- 保留 Electron + 原生 HTML/CSS/JavaScript，不新增 React、Tailwind、图标包、字体包或前端构建链。
- `08-08-universal-entry-recovery` 已完成并归档，GUI 行为基线为提交 `6421685`。禁止覆盖“继续等待 3 分钟”、人工接管关联重试及其后端动作契约。
- Electron 默认窗口 900×650，最小窗口 800×600；这些尺寸是正式验收目标，不按浏览器移动端页面处理。
- 后端 `available_actions` 是所有运行控制的唯一真源；GUI 不从状态名称、阶段名称或日志文本自行推导按钮权限。
- 外部项目只提供设计经验，不复制代码、主题、图片、字体或业务素材。

## 3. 总体信息架构

~~~text
应用框架
├─ 可折叠一级导航
│  ├─ 运行
│  ├─ 工作流
│  ├─ 历史
│  └─ 设置
├─ 全局顶部状态栏
│  ├─ 当前页面标题
│  ├─ 后端连接状态
│  ├─ 当前运行摘要 / 查看运行
│  ├─ 紧急停止（仅后端允许时）
│  └─ 浅色 / 深色快捷切换
└─ 主工作区
   ├─ 运行：任务选择、配置、运行现场、详情标签
   ├─ 工作流：列表视图 / 独立编辑视图
   ├─ 历史：表格视图 / 独立详情视图
   └─ 设置：外观与当前真实可用的应用信息
~~~

原“进度”一级页面取消，其有效信息并入“运行”。原固定右侧证据栏取消，完整过程放入运行页的“时间线 / 证据 / 日志”标签区。

## 4. 应用框架与响应式布局

应用只保留两层固定结构：一级导航与内容列。顶部状态栏属于内容列，不再叠加独立的全局运行按钮条。

| 窗口宽度 | 一级导航 | 任务列表 | 主工作区 |
| --- | --- | --- | --- |
| 800-899 | 自动折叠为图标栏 | 抽屉 | 单列，关键运行信息优先 |
| 900-1099 | 默认显示图标与文字，可手动折叠 | 抽屉 | 单列或局部双列 |
| ≥1100 | 显示图标与文字，可手动折叠 | 次级侧栏 | 任务详情/运行现场主列 |

断点只控制布局，不重置 `selectedScriptId`、当前页面、详情标签、工作流草稿或历史筛选。抽屉和固定栏不得形成互相竞争的嵌套滚动区域。

## 5. 主题与视觉系统

### 5.1 主题状态

- 在 `<html>` 上使用 `data-theme="light|dark"`。
- `localStorage` 保存单一主题值；无保存值时固定使用 `light`，不自动跟随系统主题覆盖用户要求。
- 页面加载时在主样式生效前恢复主题，避免先深后浅或先浅后深的闪烁。
- 顶部快捷按钮和设置页外观选项读写同一主题函数，不维护两份状态。

### 5.2 设计令牌

CSS 只通过语义令牌表达颜色与层级，例如：

- 表面：`--canvas`、`--surface`、`--surface-raised`、`--surface-muted`。
- 文本：`--text-primary`、`--text-secondary`、`--text-disabled`。
- 边界：`--border`、`--border-strong`、`--focus-ring`。
- 品牌：`--accent` 使用克制朱红，`--accent-secondary` 使用少量暖金。
- 状态：`--status-running`、`--status-success`、`--status-warning`、`--status-error`、`--status-paused`。
- 尺寸：4/8 间距阶梯、三档圆角、两档阴影、统一图标尺寸和 160/220ms 动效时长。

浅色主题使用暖中性底色与白色表面，深色主题单独映射表面与文本，不做简单反相。实施时用实际颜色值验证正文 4.5:1、较大文字和非文本控件 3:1 的最低对比度。

### 5.3 品牌与图标

- 使用系统字体栈，优先 `Segoe UI`、`Microsoft YaHei UI`、`Microsoft YaHei`，不依赖网络字体。
- 阴阳师气质只体现在品牌标记、少量朱红/暖金、印章式几何细节，不使用游戏截图背景或复杂纹理。
- 仅保留实际需要的本地 SVG symbol；相同层级保持统一描边、尺寸和对齐，不引入整套图标依赖。

## 6. 运行工作台

### 6.1 空闲态

- 紧凑任务列表负责选择、分类和状态，不在列表行内嵌入配置表单。
- 单一详情面板展示任务说明、schema 驱动配置和唯一“启动任务”主操作。
- 配置字段继续使用后端 `config_schema`，保留类型、默认值、范围、说明、单位和敏感性语义。

### 6.2 运行态与终态

- 页面骨架保持稳定；运行开始后任务配置自动折叠，运行身份、阶段、进度和可用操作提升为首屏重点。
- 用户可以重新展开任务区，但不得启动第二个任务或误以为配置会热更新当前 run。
- 失败时首屏显示错误码、用户可理解的说明、最新证据缩略图和后端允许的恢复操作。
- 终态突出结果摘要、耗时、关键证据和再次运行/查看历史入口。

### 6.3 详情标签

- 时间线：按事件序号展示阶段变化与关键动作，不解析日志文本生成状态。
- 证据：展示真实截图或明确的 `capture_error`，不渲染虚假路径。
- 日志：保留级别筛选和清空当前显示；日志只是证据，不决定运行状态。

三个标签消费同一 current run 数据和事件序号，切换标签不得触发新的运行状态副本。

## 7. 工作流、历史与设置

### 7.1 工作流

- 列表与编辑器是主工作区内两个子视图。
- 编辑器沿用现有 workflow/step schema、失败策略与调度字段，不改变业务语义。
- 草稿状态单独记录；返回、切换一级页面或关闭编辑视图前检查 dirty，保存成功后清除 dirty。
- 工作流运行后切换到运行页并由 current run 快照接管展示。

### 7.2 历史

- 默认表格列：任务、状态、开始时间、耗时、来源、错误码。
- 800×600 下隐藏来源等次要列，并在任务单元格内用第二行保留核心摘要，不出现横向滚动。
- 详情是独立子视图；进入前保存筛选、页码和滚动位置，返回后恢复。
- 详情组合后端返回的配置、工作流步骤、日志、快照、证据和 `available_actions`，不在前端拼数据库字段。

### 7.3 设置与反馈

- 设置页只展示真实有效的能力：外观主题，以及仓库已有接口能够确认的连接/应用说明；不放置无效开关或未来功能占位。
- 短操作使用 `aria-live="polite"` 的 Toast；危险失败可使用 `role="alert"`。Toast 不夺取焦点。
- 不新增通知抽屉。运行中跨页状态由顶部状态栏承担，终态由历史页承担。

## 8. 前后端数据流

~~~text
REST current snapshot ─┐
                      ├─> state.currentRun ─> 顶部摘要 / 运行现场 / 操作可见性
WebSocket run_snapshot ┘

WebSocket seq events ───> 日志与时间线增量；重复 seq 丢弃
config_schema ──────────> 单一配置表单
history list/detail ────> 历史表格 / 独立详情
localStorage theme ─────> html[data-theme] / 顶部与设置页主题控件
~~~

网络和持久化契约不因视觉重构改变。若实施发现某项展示确实缺字段，先证明现有接口无法表达，再以最小后端扩展更新父 PRD 和对应子任务设计。

## 9. 代码边界

- 优先重排现有 `gui/index.html`、`gui/styles.css`、`gui/renderer.js`，不预先创建组件框架。
- 只在纯状态推导需要独立 Node 测试或同一逻辑出现第二个消费者时提取小型模块；新增文件后同步 `gui/package.json` 的显式打包文件列表。
- API 请求、WebSocket、HTML 转义、配置值归一化等已有公共函数继续复用，不为每个页面复制一套。
- 当前运行操作使用一个共享的 action→endpoint 映射；顶部停止和运行页按钮都调用同一控制函数。

## 10. 兼容、发布与回滚

### 兼容

- 保留托盘暂停/停止、窗口尺寸持久化、脚本启动、配置保存、工作流 CRUD/运行、历史过滤分页、证据读取和恢复操作。
- 不改变 API 路径、状态枚举、单执行槽和旧 SQLite 数据。
- `08-08-universal-entry-recovery` 增加的阶段、继续等待和关联重试必须进入回归矩阵。

### 发布顺序

1. 视觉基础与应用框架。
2. 运行工作台。
3. 工作流、历史与设置。
4. 父任务执行最终跨阶段视觉与契约验收。

### 回滚

每个子任务单独提交并保持可运行。若后续阶段失败，可回滚该阶段而保留已验收的应用框架或运行工作台；禁止用回滚覆盖当前工作树中不属于本任务的改动。
