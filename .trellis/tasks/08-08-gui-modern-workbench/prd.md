# GUI 现代化工作台重构

## Goal

在不削弱现有运行、恢复、编排和历史契约的前提下，把当前 Electron GUI 重构为更现代、清晰且状态可信的自动化任务工作台，使用户能顺畅完成“选择任务—配置—启动—观察—恢复—复盘”的完整闭环。

## Background

- 外部项目学习结论建议吸收 OnmyojiAutoScript 的任务生命周期与运行证据设计，以及 Whimbox 的任务型信息架构、状态驱动交互、非阻塞进度反馈和可复用配置表单；不迁移外部项目技术栈或素材（`docs/2026-08-08-external-project-learning-conclusions.md:8-26`、`:134-149`、`:165-220`）。
- 运行可靠性与调度 P0/P1 已由归档 Trellis 任务完成；REST、WebSocket 和 GUI 已共享规范化运行快照，按钮由 `available_actions` 驱动，历史、证据和最小周期调度已有后端基础（`.trellis/tasks/archive/2026-08/08-08-desktop-workbench-p0-p1/prd.md`）。本任务不重复建设这些能力。
- 当前页面采用四栏固定布局：图标栏、脚本栏、主工作区、证据侧栏；一级入口为执行、编排、进度、历史日志和设置（`gui/index.html:10-132`）。
- 当前前端为无构建链的原生 HTML/CSS/JavaScript；`renderer.js` 约 1444 行，集中承担 API、全局状态、模板渲染、WebSocket、页面切换与事件绑定，组件边界较弱。
- 当前 Electron 默认窗口为 900×650，最小窗口为 800×600（`gui/main.js:17-19`、`:302-305`）；现有四栏布局在该尺寸下信息拥挤，是布局重构必须覆盖的真实约束。
- `08-08-universal-entry-recovery` 已完成并归档；相关 GUI 能力已由 `6421685 feat(workbench): 入口阶段运行管理与关联重试` 提交，当前 GUI 工作树无未提交差异。本任务以该提交后的行为为基线，不得回退“继续等待 3 分钟”和人工接管关联重试。

## Requirements

### R1 信息架构与核心闭环

- 导航和页面内容按用户任务组织，不按 Python 模块组织。
- 一级导航收敛为“运行、工作流、历史、设置”；当前独立的“进度”页面并入“运行”页面，不再保留重复入口。
- 一级导航使用“统一 SVG 图标 + 文字标签”的可折叠侧边栏；默认窗口显示文字，800×600 或用户主动收起时进入图标模式，当前页面同时使用背景、文字和侧边标记表达选中状态。
- 工作流列表与编辑器使用主工作区内的列表/编辑视图切换，不再用长表单模态框承载新建和编辑；编辑视图必须提供返回、保存和未保存离开确认。
- 执行页必须在首屏呈现连接状态、当前任务、运行阶段、进度、主要操作、失败原因和恢复入口。
- “运行”页保持导航与页面骨架稳定，但按运行状态调整内容优先级：空闲时展开任务选择和配置；运行开始后折叠配置并突出运行现场；结束后突出结果、失败证据或再次运行入口。用户始终可以手动重新展开任务区。
- 移除固定占宽的右侧证据栏；运行页首屏保留关键失败摘要、最新截图缩略图和恢复入口，完整过程按“时间线、证据、日志”三个标签收敛到详情区。
- 任务选择采用“紧凑任务列表 + 单一任务详情/配置面板”：列表只展示任务身份、分类和状态；选中后由唯一详情区展示说明、配置与启动操作，不再在每张任务卡片内展开完整表单。
- 历史页采用适合批量扫描的紧凑表格，核心列为任务、状态、开始时间、耗时、来源和错误码，并提供状态、任务和时间筛选；不继续使用逐条占据大面积空间的卡片列表。
- 历史详情在主工作区内使用独立详情视图，完整展示运行摘要、配置、步骤时间线、证据、日志和合法恢复操作；返回列表时恢复原筛选、页码与滚动位置，不使用狭窄右侧抽屉承载详情。
- 全局顶部状态栏在所有一级页面显示后端连接、当前任务和运行状态，并提供“查看运行”入口；运行中额外保留紧急“停止”快捷操作，不在全局重复展示完整恢复按钮组。
- 任务配置、实时运行、历史复盘和工作流编辑职责清晰；长时间运行不使用持续遮挡主界面的模态框。
- 页面切换后仍能看到并操作当前运行，且不丢失筛选、选择和展开状态。

### R2 整体视觉现代化

- 默认使用清爽、低干扰的浅色工作台主题，并提供可由用户主动切换的深色主题；主题选择在应用重启后保持。
- 浅色与深色主题共享同一套语义令牌和信息层级，不允许深色主题仅通过颜色反转临时生成。
- 全局顶部状态栏提供太阳/月亮 SVG 快捷切换；设置页“外观”区提供明确的“浅色/深色”选项和持久化说明，两处读写同一主题状态。
- 建立最小设计令牌：颜色、字体层级、4/8 间距、圆角、边框、阴影、图标尺寸、动效时长和层级。
- 视觉以专业工具型工作台为主体，只使用少量阴阳师气质作为品牌点缀，例如克制的朱红、暖金或印章式几何元素；不使用大面积游戏背景和复杂纹理。
- 结构性图标统一使用本地 SVG 图标，不继续使用字体符号或 emoji；不新增网络字体或运行时外部资源依赖。
- 信息层级主要依靠排版、留白和表面层级；颜色只表达状态和主操作，不单独承担语义。

### R3 状态驱动交互

- 运行操作继续以后端 `available_actions` 为唯一真源；GUI 不根据日志文本或本地状态猜测可用操作。
- 每个页面只突出一个主操作；暂停、恢复、停止、重试、跳过、继续等待和人工接管按当前状态动态呈现。
- 危险操作有明确确认，异步操作有进行中、成功和失败反馈，错误信息包含可执行的恢复路径。
- 日志、通知、截图证据和当前进度各自承担明确职责，避免同一事实在多个卡片中重复且不同步。
- 不新增全局通知抽屉：短时操作使用可访问的 Toast，长任务使用持续可见的顶部运行状态区，错误与恢复留在运行页，终态记录进入历史页。
- 顶部紧急停止与运行页完整操作都必须消费同一 `available_actions`；暂停、恢复、继续等待、重试、跳过和人工接管只在运行页完整呈现。

### R4 布局与适配

- 完整支持现有 800×600 最小窗口和 900×650 默认窗口；窄窗口优先保留当前运行、主操作和错误恢复，次要信息可折叠或切换展示。
- 在常见 1280×720 及更大窗口中充分利用横向空间，但不制造超过必要数量的固定栏和嵌套滚动区。
- 不再使用“图标栏 + 脚本栏 + 主工作区 + 证据栏”的四栏固定布局；运行详情标签区使用同一数据源展示时间线、截图证据和日志。
- 任务列表在宽窗口作为次级侧栏，在窄窗口收进可关闭抽屉；抽屉开关和选中任务均可通过键盘操作。
- 历史表格在窄窗口隐藏次要列并将核心信息收敛为两行摘要，不依赖横向滚动查看关键状态。
- 折叠后的全局导航仍提供 Tooltip、可访问名称和完整键盘操作；展开/折叠不得重置当前页面或运行状态。
- 固定栏、浮动运行控制和模态框不得遮挡可滚动内容；主内容区不出现非预期横向滚动。

### R5 可访问性与感知质量

- 正文与背景对比度达到 WCAG AA；重要状态同时使用文字、图标和颜色。
- 所有交互元素具备可见的 hover、pressed、disabled 和 `:focus-visible` 状态，并可通过键盘完成核心流程。
- 动效限于 150-300ms 的状态过渡，表达因果关系且支持 `prefers-reduced-motion`；不增加装饰性动画依赖。
- 表单使用可见标签、说明、单位、范围和就地错误；不得只用 placeholder 或 title 承担说明。

### R6 技术与兼容边界

- 默认继续使用现有 Electron + 原生 HTML/CSS/JavaScript，不为视觉改造引入 React、Tailwind、组件库或新的前端构建链。
- 允许按页面/职责拆分现有前端文件和渲染边界，但不得改变后端运行契约、单执行槽或现有任务默认行为。
- 仅当真实交互无法由现有接口表达时，才允许增加最小后端字段或接口；任何跨层变更必须保持 REST、WebSocket、持久化快照和 GUI 一致。
- 现有执行、编排、进度、历史、设置、托盘控制、配置 schema、恢复动作和空数据降级行为必须保留或得到明确替代；原“进度”页的信息必须完整迁移到“运行”页。

## Acceptance Criteria

- [ ] AC1：用户从启动应用到开始一个手动任务，只需沿单一清晰主路径完成任务选择、配置确认和启动；页面不存在两个同等强调的主操作。
- [ ] AC1a：用户从工作流列表进入独立的新建/编辑视图，可返回或保存；存在未保存修改时，返回、切换一级页面或关闭编辑视图都会获得明确提醒。
- [ ] AC1b：“运行”页在空闲、运行中和终态之间保持页面骨架稳定，只改变内容展开状态与视觉优先级；运行开始后任务配置自动折叠但可手动恢复，当前运行控制不发生不可预测的位置跳跃。
- [ ] AC1c：任务列表只承担选择、分类和状态展示；任一时刻最多有一个任务详情/配置面板和一个主启动按钮。800×600 下列表可作为抽屉打开、选择和关闭，选中任务及未提交配置不会意外丢失。
- [ ] AC2：执行页在 800×600、900×650 和 1280×720 三种窗口尺寸下均能看到当前运行身份、阶段、进度、主操作和错误恢复入口，无横向滚动或关键控件遮挡。
- [ ] AC3：一级导航仅保留“运行、工作流、历史、设置”；原“进度”页的有效信息完整并入“运行”页。运行中切换页面后，当前运行状态及所有后端声明的可用操作仍可访问；刷新或 WebSocket 重连后结果一致。
- [ ] AC3a：默认窗口显示带图标与文字的一级导航；800×600 或用户主动收起时切换为纯图标模式，Tooltip、无障碍名称、键盘焦点和当前页选中状态仍完整可用，切换不丢页面上下文。
- [ ] AC3b：所有一级页面的顶部状态栏显示连接与当前运行摘要，并能返回运行页；仅当后端允许 `stop` 时显示紧急停止快捷操作，其他完整恢复操作不在全局重复渲染。
- [ ] AC4：暂停、恢复、停止、继续等待、重试、跳过和人工接管的显示/禁用状态完全由同一规范化快照驱动，现有 `08-08-universal-entry-recovery` 行为不回归。
- [ ] AC5：历史详情能从失败摘要进入关联日志、截图证据和可执行恢复路径；不要求用户在整段实时日志中手工定位失败。
- [ ] AC5a：运行页不保留固定右侧证据栏；首屏失败摘要能直接看到最新证据缩略图和恢复入口，用户可在“时间线、证据、日志”标签间切换查看完整详情，切换不丢当前运行状态。
- [ ] AC5b：短操作反馈不会阻塞页面且可被辅助技术感知；运行中切换页面仍可通过顶部运行状态区查看状态并返回运行页；终态结果可在历史页复盘，界面不存在与这些职责重复的通知抽屉。
- [ ] AC5c：历史页默认以紧凑表格展示任务、状态、开始时间、耗时、来源和错误码，可按状态、任务和时间筛选；800×600 下核心信息完整可见且无横向滚动。
- [ ] AC5d：从历史表格打开独立详情视图后，可查看运行摘要、配置、步骤时间线、证据、日志和后端允许的恢复操作；返回时恢复原筛选、页码与滚动位置。
- [ ] AC6：配置表单展示可见标签、说明、单位、范围、默认值和错误反馈；敏感字段保持遮蔽，新增脚本仍通过现有 schema 通用渲染。
- [ ] AC7：首次启动默认使用浅色主题，用户可切换深色主题且重启后保持选择；两个主题均使用统一语义令牌和单一 SVG 图标语言，状态不只依赖颜色，正文对比度达到 WCAG AA，键盘焦点清晰，并支持减少动效。
- [ ] AC7a：顶部快捷按钮与设置页外观选项始终显示同一主题状态；任一入口切换后页面即时更新，重启应用后保持选择，首次无保存值时使用浅色主题。
- [ ] AC8：现有 Electron 默认/最小窗口、托盘命令、脚本启动、工作流 CRUD/立即运行、历史过滤分页、证据展示和设置说明均保留可用，不因页面重构改变业务语义。
- [ ] AC9：前端语法检查、现有 GUI 后端检测、受影响的 UI 后端契约测试和新增最小 DOM/交互回归测试通过；真实 Electron 页面完成一次人工视觉验收。

## Out of Scope

- 不迁移 PySide/QML，不复制外部项目代码、图片、字体或品牌素材。
- 不新增 AI 聊天首页、多客户端并行、复杂诊断工具、OCR/ROI 编辑器或运行时本身的新失败策略。
- 不为尚未实现的后端能力新增可点击入口或空壳页面。
- 不在本任务中修改具体游戏脚本的识别、导航、点击或战斗逻辑。

## Delivery Stages

1. `08-08-gui-shell-theme`：浅色默认双主题、设计令牌、可折叠导航、顶部状态栏和响应式应用骨架。
2. `08-08-gui-run-workbench`：任务列表/详情、状态自适应运行现场，以及时间线/证据/日志详情区；依赖阶段 1。
3. `08-08-gui-secondary-views`：工作流独立编辑、历史表格/详情、设置与全局反馈，并完成整体验收；依赖阶段 1 和阶段 2。

父任务只拥有总需求、跨阶段验收和最终集成评审，不作为直接实现目标。三个子任务按上述顺序实施；阶段 1 以已提交并归档的 `08-08-universal-entry-recovery` 为恢复行为基线。
