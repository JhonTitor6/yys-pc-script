# GUI 运行工作台设计

## 1. 页面结构

~~~text
运行页
├─ 任务区
│  ├─ 任务列表 / 窄屏抽屉
│  └─ 单一任务详情与配置
└─ 运行现场
   ├─ 运行身份、阶段、进度、操作
   ├─ 失败或终态摘要
   └─ 时间线 / 证据 / 日志标签
~~~

空闲时任务区是主要内容；运行中运行现场是主要内容。只切换展开状态和视觉权重，不替换整个页面根节点。

## 2. 前端状态

在现有 `state` 中保留或增加最少的视图状态：

- `selectedScriptId`
- `taskPanelExpanded`
- `taskDrawerOpen`
- `runDetailTab`：`timeline|evidence|logs`
- `currentRun`
- `logs` 与 `lastEventSeq`

布局断点不得修改任务选择和配置 DOM 的值。运行开始只折叠任务面板，不销毁用户刚提交的配置摘要。

## 3. 任务列表与配置

- 任务列表只显示 display name、分类、稳定/实验状态和当前运行标记。
- 选中后使用现有 `renderField` 和 `normalizeConfigValue` 生成单一表单。
- 描述、单位、范围使用可见辅助文本，不再只放在 `title`。
- 运行中再次展开任务详情时明确显示“修改只影响下一次运行”，不制造热更新假象。
- 启动仍先保存配置，再调用 `/api/runs/start`。

## 4. 运行状态呈现

- `renderCurrentRun` 继续接收规范化快照，但将输出拆成身份、进度、错误摘要、动作组和详情标签几个局部渲染函数。
- 操作按钮统一遍历 `available_actions`；顶部停止和运行页停止调用相同 `controlCurrentRun`。
- stage label 只是文案映射，不参与权限判断。
- 无 current run 时显示有行动建议的空状态，不伪造进度或证据。

## 5. 时间线、证据与日志

- 时间线优先使用现有事件序号和后端阶段/快照记录；若当前 API 没有完整历史事件，不用日志文本伪造，只展示真实可获得的阶段变化和时间戳。
- 证据使用 current run 的 `evidence`/`latest_evidence`；捕获失败展示 `capture_error`。
- 日志复用现有 `LOG_LIMIT`、级别过滤和转义逻辑。
- 标签切换只控制展示，不重新请求或复制 current run；必要的历史详情请求由阶段 3 负责。

## 6. 响应式行为

- ≥1100：任务列表次级侧栏 + 详情/运行现场主列。
- <1100：任务列表进入抽屉，主区显示详情或运行现场。
- 运行操作允许换行，但紧急停止与当前主要恢复操作保持可见。
- 失败截图使用固定比例容器，声明尺寸，避免加载后布局跳动。

## 7. 兼容与回滚

- 保留所有现有 action endpoint、配置 schema 和 WebSocket 去重逻辑。
- 原进度页节点只有在运行页完成同等信息后才删除。
- 本阶段独立提交；回滚不影响阶段 1 的主题与应用壳层。
