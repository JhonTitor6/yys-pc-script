# GUI 运行工作台重构

## Goal

在阶段 1 的应用骨架上，将当前脚本卡片、进度页、实时日志和证据栏收敛为一个状态可信的运行工作台，让用户顺畅完成任务选择、配置、启动、观察、恢复和查看结果。

## Background

- 父任务：`08-08-gui-modern-workbench`；依赖 `08-08-gui-shell-theme` 完成。
- 现有脚本列表在每张卡片内展开配置，脚本增加后纵向空间和操作层级会迅速膨胀。
- 当前运行摘要、独立进度页、右侧快照/证据/关键日志和中央实时日志重复展示相近事实。
- 已归档的 `08-08-universal-entry-recovery` 在提交 `6421685` 中新增继续等待、人工接管和关联重试，本阶段必须完整保留。

## Requirements

- 任务选择改为紧凑列表 + 单一详情/配置面板；任一时刻只有一个主启动按钮。
- 宽窗口任务列表为次级侧栏，窄窗口为可关闭抽屉；选择和抽屉支持键盘，未提交配置不会因布局变化丢失。
- 配置继续由 `config_schema` 通用生成，显示标签、说明、单位、范围和默认值，保持敏感字段遮蔽与原始类型转换。
- 运行页骨架稳定：空闲突出任务配置，运行开始后自动折叠配置并突出运行身份、阶段、进度和操作，终态突出结果与后续入口。
- 原“进度”页全部有效信息并入运行页并删除重复一级入口。
- 移除固定右侧证据栏；首屏失败摘要显示错误码、说明、最新截图缩略图和恢复操作。
- 完整过程使用“时间线 / 证据 / 日志”标签区；日志保留级别筛选，证据只展示真实截图或 `capture_error`。
- 暂停、恢复、停止、继续等待、重试、跳过、人工接管完全由 `available_actions` 驱动并复用同一 action→endpoint 映射。

## Acceptance Criteria

- [ ] S2-AC1：空闲时可从任务列表选择一个任务，在单一详情面板查看说明、修改 schema 配置并通过唯一主按钮启动。
- [ ] S2-AC2：800×600 下任务列表通过抽屉完成打开、选择、关闭；900×650 和 1280×720 下关键操作不被遮挡或产生横向滚动。
- [ ] S2-AC3：任务开始后配置自动折叠但可手动展开，运行身份、阶段、进度和合法操作保持稳定可见，不出现突兀整页重排。
- [ ] S2-AC4：原进度页的运行阶段、计数、来源和快照信息完整并入运行页，一级导航不再存在进度入口。
- [ ] S2-AC5：失败首屏直接显示错误、最新证据和恢复入口；时间线/证据/日志标签可查看完整详情且不产生第二份运行状态。
- [ ] S2-AC6：暂停、恢复、停止、继续等待、重试、跳过和人工接管的显示与禁用完全匹配后端 `available_actions`。
- [ ] S2-AC7：继续等待调用 `continue-waiting`，人工接管调用 `manual-takeover`，manual 历史关联重试仍创建新 run；既有恢复行为不回归。
- [ ] S2-AC8：配置下拉值保持 schema 原始类型，敏感字段不泄露；新增任务仍无需复制整页 HTML。
- [ ] S2-AC9：刷新或 WebSocket 重连后从规范化快照恢复相同运行现场、标签数据和控制权限。
- [ ] S2-AC10：Node 检查、GUI 测试和受影响 UI 后端契约测试通过，并完成真实 Electron 运行页视觉验收。

## Out of Scope

- 不改工作流编辑器、历史表格/详情和设置页最终形态。
- 不新增运行状态、失败策略、证据类型或后端推断逻辑。
- 不修改游戏脚本配置含义和运行行为。
