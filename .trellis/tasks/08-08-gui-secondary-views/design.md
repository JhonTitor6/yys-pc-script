# GUI 工作流、历史与设置设计

## 1. 页面子视图状态

一级 view 仍为 `workflows`、`history`、`settings`，页面内部使用最小子视图状态：

- 工作流：`list|editor`，附 `editingWorkflowId`、`dirty`、草稿与展开步骤。
- 历史：`list|detail`，附筛选、offset/limit、选中 run、返回滚动位置。
- 设置：单页分区，不建立插件式设置框架。

一级导航切换前统一调用当前子视图的离开守卫；只有工作流 dirty 时需要确认。

## 2. 工作流编辑

- 将现有 modal 表单结构迁移到主工作区编辑视图，复用 `renderModalStepAccordion` 等实际步骤渲染逻辑并按职责重命名，不复制一套新编辑器。
- 页面头部提供返回、标题和唯一保存主操作；添加步骤是次级操作。
- dirty 由字段 input/change、步骤新增/删除/展开后的真实修改触发；仅展开手风琴不应误标 dirty。
- 保存异步期间禁用重复提交并显示进行中；失败后保留输入与当前展开步骤。

## 3. 历史表格与详情

### 列表

- 复用现有 `/api/runs` 过滤分页接口；若当前 API 不支持任务/时间筛选，先确认能否客户端对当前页过滤。只有产品要求必须跨页准确筛选且现有 API 无法表达时，才规划最小查询参数扩展。
- 宽屏显示六个核心列；窄屏将任务、状态、时间、错误摘要合并到两行单元格，来源等次要列隐藏。
- 行可用鼠标和键盘进入详情，当前排序/筛选状态有可访问名称。

### 详情

- 使用现有 `/api/runs/{id}` 返回的 workflow/step、config、logs、snapshots、evidence。
- 配置按 schema 格式化并遮蔽敏感字段，不直接展示原始 JSON 作为主要界面；必要时日志/调试区域可展开原始信息。
- 返回列表恢复过滤器值、页码和滚动位置。
- 恢复按钮继续受详情状态或后端动作字段约束；不得从错误文本猜测。

## 4. 设置与主题

- “外观”分区提供浅色/深色选择，调用阶段 1 的共享 `setTheme`。
- 可显示真实连接方式、当前能力限制或应用版本，但只读信息必须与禁用控件视觉区分。
- 不为通知、游戏窗口、数据目录等未具备保存接口的能力放置假开关。

## 5. Toast

- 单一 Toast 容器，短消息排队或替换，避免多处堆叠。
- 普通成功/信息使用 `aria-live="polite"`，需要立即注意的失败使用 `role="alert"`。
- 自动消失前提供足够阅读时间；重要失败同时留在页面，不只依赖 Toast。
- Toast 不用于长任务进度，也不形成历史消息中心。

## 6. 集成边界

- 工作流立即运行后切换到运行页，由 current run 快照负责后续状态。
- 历史关联重试创建新 run 后切换到运行页或提供明确查看入口，不修改原历史记录。
- 顶部状态栏、设置主题和运行停止共用阶段 1/2 已有函数，不复制状态。

## 7. 兼容与回滚

- 先让新工作流编辑视图与旧 modal 共享渲染/保存逻辑，验证后再删除 modal DOM。
- 先完成历史表格和详情上下文恢复，再删除旧卡片/详情布局。
- 本阶段独立提交；回滚保留阶段 1 和阶段 2。
