# 修复斗技左二槽位错位点击

## Goal

斗技配置为己方左2时，只在识别出真实第二槽位后点击；画面干扰导致槽位不完整或不可信时继续等待，不能把左1误报为“左2定位成功”。

## Background

- 2026-08-29 17:38:20 的运行日志显示“左2延迟定位成功”，实际点击坐标为 `(189, 398)`，用户观察到点击了左1。
- 同次运行中真实左2的稳定识别坐标约为 `(408, 382)`。
- 当前 `_find_douji_slot_anchors()` 对全屏血条候选做链式聚类，仅校验最终簇数是否为 5；左侧干扰簇与右侧真实槽位合并同时发生时，数量仍可为 5，但槽位序号整体错位。

## Requirements

- 保留现有血条颜色识别、点击偏移、延迟重试、战斗结束清理待定位状态的行为。
- 将五个己方槽位按 `1136×640` 基准画面的预期横向锚点分类，并随实际截图宽度等比缩放。
- 每个槽位只能从自身锚点容差范围内选择候选；非中央槽位优先选择横向最接近期望锚点的候选，中央槽位继续选择更下方的己方血条。
- 任一槽位缺少可信候选时返回定位失败，由现有 `_douji_target_pending` 流程继续重试，不执行固定坐标兜底。
- `frame` 参数只影响候选识别和缩放；`slot` 参数只选择对应槽位及其既有点击偏移，不得改变其他槽位的定位结果。
- 仅修改斗技定位实现和对应单元测试，保留 `gui/installer.nsh` 等无关未提交改动。

- [x] 标准五槽位画面中，左2、左4及既有中央干扰处理结果不变。
- [x] 缺少任一真实槽位时返回 `None`，运行流程保持待定位状态且不停止脚本、不盲点。
