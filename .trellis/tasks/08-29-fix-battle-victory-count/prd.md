# 修复战斗胜利次数计数错误

## Goal

修复斗技结算画面被连续识别时重复累计胜利次数的问题，使日志中的胜利次数等于实际获胜场次。

## Background

- `yys/douji/yys/logs/douji/2026-08-29.log:84-98` 显示已战斗 24-29 场时胜利数达到 59，违反“胜利场次不得超过已完成场次”的业务约束。
- `win_util/event.py:149-166` 每轮截图都会触发首个匹配事件，不会对连续画面自动去重。
- `yys/douji/douji_script.py:246-251` 每次识别胜利图都会无条件递增胜利次数，因此同一结算画面会被重复计数。
- 公共基类的不同子类具有不同结算生命周期，本次只修改已确认发生问题的斗技流程。

## Requirements

- 同一场斗技中，无论胜利结算图被连续识别多少次，胜利次数只能增加一次。
- 进入下一场斗技后，新的胜利仍能正常增加一次。
- 点击结算画面、总战斗次数、己方槽位待定位状态和自动停止条件保持现有行为。

## Acceptance Criteria

- [x] 连续两次调用斗技胜利回调时，胜利次数只增加一次，但两次结算点击仍照常执行。
- [x] 识别到下一场斗技入口后，再调用胜利回调会增加第二次胜利。
- [x] 斗技现有单元测试及新增回归测试通过。
- [x] `git diff --check` 通过，且不改动用户已有的 `gui/installer.nsh` 工作区变更。

## Out of Scope

- 不回写或推算当前运行日志中已经错误累计的历史胜利次数。
- 不重构公共事件系统或其他脚本的结算状态机。

## Notes

- 本任务为单模块、单状态修复，采用 PRD-only 轻量任务流程。
