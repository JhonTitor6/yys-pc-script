# 定时执行狭间暗域与安全回首页

## Goal

在桌面工作台增加独立的“定时任务”模块，让用户按间隔、每日、每周或指定日期时间调度单个脚本或现有工作流；狭间暗域无论手动还是定时启动，都优先从当前场景走可验证的最短入口，仅在没有可靠路径时安全回首页兜底。

## Background

- 当前工作流同时承载编排与调度字段，GUI 在 `gui/renderer.js:771-780` 展示自动调度并预填时间，后端在 `ui_backend/scheduler/service.py:93-136` 仅支持手动、间隔和每日定时。
- GUI 新建工作流不提交 `next_run_at`；`SchedulerService.preview_workflow()` 在每轮轮询中把空值重新计算到未来，导致任务可能永不到期。根因位于持久化调度状态，而不是狭间脚本内部计时。
- SQLite 已持久化工作流、步骤、运行历史和调度时间，`RunManager` 已保证单运行槽；本任务复用这些能力，不新增第二套调度线程或外部调度器。
- `SceneManager.get_shortest_path()` 已提供已知场景的最短路径；狭间暗域当前在 `yys/abyss_shadows/abyss_shadows_script.py:936-970` 支持从首页进入，也支持从已识别的狭间区域或敌人选择页续跑。
- 通用 `EntryPreparer` 的共享安全契约是未知画面零输入，因此本任务不得为所有脚本放宽该行为。狭间暗域的专用入口才允许执行本需求定义的 `ESC` 兜底。
- 用户已确认：首页按 `ESC` 会出现“确认离开”弹窗；弹窗中再按一次 `ESC` 会取消并回到首页。该弹窗只能作为首页层级哨兵，绝不能确认退出。

## Requirements

### R1 独立定时任务与执行目标

- GUI 增加独立“定时任务”一级入口，提供列表和新建/编辑视图，可新增、编辑、启用、停用、删除和立即运行任务；已结束的仅一次任务按 AC8 立即运行后仍保持停用。
- 列表至少展示任务名、执行目标、周期、下一次运行、30 分钟默认补跑宽限期、当前/最近状态，以及可用操作。
- 调度配置统一在新模块管理；工作流编辑器移除触发方式和“启用自动调度”，只保留步骤编排、失败策略与手动运行。
- 定时任务可直接选择单个脚本，也可实时引用现有工作流。多脚本步骤、顺序和失败策略仍只在工作流模块编辑，定时任务模块不复制步骤编辑器。
- 工作流的后续编辑从下一次定时运行起生效；已经启动的运行继续使用启动时快照，不被中途改写。
- 工作流目标的每个已启动轮次（含定时任务的立即运行）保存并在运行历史展示当轮完整工作流快照，包含全部步骤、顺序、参数及失败策略，包括未执行步骤。后续修改或删除原步骤不得改变本轮执行与历史展示；未执行步骤必须与实际执行记录区分。（2026-09-05 用户确认）
- 单脚本任务创建时以脚本当前配置初始化，并独立持久化参数；之后修改全局脚本配置不得改变该任务。
- 每条任务只配置一个执行时刻；同一目标需要多个时刻时创建多条任务。
- 工作流被定时任务引用时禁止删除，必须先删除任务或更换目标。单脚本目标因版本变化而缺失时，任务安全停用并显示目标缺失，不创建运行或发送输入。

### R2 调度与补跑语义

- 支持四种周期：按间隔、每日固定时间、每周选择一个或多个星期、指定本地日期时间仅执行一次；示例包括每天 06:00、每周三/六、每周五/六/日。
- 执行目标、周期和时间必须由用户明确选择；不预填 `09:03` 或任何其他执行时间。配置不完整或非法时不得保存或启用。
- 补跑宽限期按任务配置，默认 30 分钟，并与任务一起经 API 和 SQLite 往返。
- 新建、编辑或重新启用任务时必须计算并持久化有效 `next_run_at`；预览与实际执行使用同一个纯时间计算函数和系统本地时间。参考时间恰好等于设定时刻时按下一周期计算，不立即触发。
- 每日与每周任务按最近未来时刻调度；按间隔任务保留现有成功/失败间隔语义；仅一次任务只执行指定日期时间的一轮。
- 一个到期轮次最多触发一次。多个任务按现有优先级降序、稳定 ID 升序执行，且继续服从单运行槽，不并发启动。
- 到期时执行槽被占用，只保留当前一轮待补跑，不累计多轮；槽释放且仍在宽限期内时补跑一次，超过宽限期则跳过。工作台或后端在到期时未运行，重启后使用相同规则。
- 每日、每周和间隔任务执行、过期或中断恢复后计算下一周期。仅一次任务成功、失败、过期或中断后清空 `next_run_at`、自动停用并保留在列表，显示“已完成”“失败”“已过期”或“运行中断”。
- 已结束的仅一次任务可立即重跑；重跑复用保存目标，保持停用且不生成计划时间，列表状态更新为本次结果，此前实际运行仍保留在现有运行历史。
- 每个调度轮次的终态必须持久保存，覆盖自动执行、手动重跑、成功、失败、过期和中断；记录应包含计划时间、实际开始/结束时间和结果。执行槽占用期间的重复轮询提示不重复写入历史。
- 崩溃重启后，尚未领取的轮次沿用补跑宽限期；领取记录已保存但没有终态的轮次统一记为“运行中断”，不自动重跑，保留手动重跑入口。即使领取后尚未实际向游戏发送输入，也按中断处理；已保存终态的轮次不得重复执行或改写终态。周期任务恢复下一次计划，仅一次任务保持停用；立即重跑仍不改变自动计划。（2026-09-05 用户确认）
- 已有 `scheduled_time` 和 `interval` 工作流升级时迁移为新模块任务，保留目标、启停、触发配置、优先级、有效的 `next_run_at` 和 `last_run_at`。已有有效计划时间按原值及补跑宽限期处理；缺失计划时间时，从升级后的最近未来时刻开始，不推测过去漏跑的轮次，也不自动补跑过去的时刻。迁移只执行一次，删除迁移出的任务后重启不得重建或再次启用。（2026-09-05 用户确认）

### R3 狭间暗域最短入口与首页兜底

- 手动与定时启动调用同一套狭间入口逻辑，不因运行来源改变导航行为。
- 启动时先识别当前稳定场景：已经位于狭间区域或敌人选择页时同步业务状态并续跑；存在可验证的中途捷径时优先使用，不绕回首页。
- 已识别为 `home` 时直接复用现有 Home → 日常 → 狭间暗域录制入口，禁止先发送返回或 `ESC`。
- 没有可靠捷径或捷径后置验证失败时才回首页。对已知非首页稳定页依次尝试 `to_home.bmp`、`return.bmp`、`ESC`；每次动作后重新截图并验证，不使用固定坐标盲点。
- 未知画面先进行现有有界重识别并尝试可见、可验证的导航按钮；仍未知且无按钮时逐次发送 `ESC`，每次都重新识别。
- 同一次入口准备中的首页恢复，回首页按钮、返回按钮和 `ESC` 三类退层动作合计最多 6 次，退层阶段累计不超过 30 秒；在已知/未知页面之间切换或重试不得重置预算。战斗等待、结算关闭另行计时，返回退层阶段时保留已用次数和耗时；结算关闭与取消退出弹窗不计入退层次数，但仍受各自保护及全局运行保险丝约束。（2026-09-05 用户确认）
- 识别到 `home` 或“确认离开”弹窗时立即停止退层。出现弹窗后再发送一次 `ESC` 取消，重新稳定确认 `home` 后才进入首页流程；绝不确认退出。
- 启动入口遇到战斗时，持续截图识别，战斗进行中不点击、不发送返回或 `ESC`，最多等待 3 分钟；超时仍未确认战斗结束时返回“入口等待超时”，交给既定失败策略处理，等待期间随时响应停止。该等待单独计时，不把首页恢复的 30 秒预算用于等待战斗。（2026-09-05 用户确认）
- 识别到战斗结束页后主动点击已验证的结算/继续位置；每次点击后重新截图，逐页关闭胜利、失败、奖励或继续页，直到确认离开结算页，再重新识别当前场景并选择入口。启动时已在结算页也直接按此流程处理，不先空等 3 分钟。结算关闭不计入本轮业务战斗次数；手动与定时启动使用相同流程，所有输入通过注入环境和安全保护。（2026-09-05 用户纠正并确认）

### R4 兼容与回归边界

- 复用现有工作流执行器、步骤失败策略、运行历史、事件流和单运行槽，不在狭间脚本中创建计时线程。
- 保留狭间暗域从已知区域/敌人选择页续跑、首页拖拽入口、参数、战斗流程和后续场景切换行为。
- 保留工作流 CRUD、步骤编辑、失败策略和立即运行；仅把调度字段与启停入口迁移到定时任务模块。
- 保留现有运行/历史/设置、托盘和停止控制；新增一级导航后仍须满足 800×600 最小窗口可用性与键盘可访问性。

## Acceptance Criteria

- [ ] AC1：GUI 存在独立“定时任务”一级入口及列表/编辑视图，可新增、编辑、启用、停用、删除和立即运行；列表展示目标、周期、下一次运行、宽限期和状态，新建表单不预填任何执行时间。
- [ ] AC2：定时任务可选择单个脚本或现有工作流；单脚本参数独立持久化，工作流仍由原编辑器编排且定时任务不复制步骤编辑器。
- [ ] AC3：工作流编辑从下一次定时运行起生效，已经启动的运行不变；工作流仍被任务引用时删除请求返回可供 GUI 展示的冲突信息。
- [ ] AC4：目标、周期、时间、星期和宽限期在 API 边界被校验；每周未选星期、仅一次时间非法/已过期或其他配置不完整时不可保存或启用，合法值经 API/SQLite 往返保持一致。
- [ ] AC5：固定本地时间测试覆盖每日当天/次日、恰好到点排下一周期、每周三/六、每周五/六/日、仅一次及按间隔的下一次时间；预览与执行结果一致。
- [ ] AC6：`next_run_at` 在创建、编辑、启用和应用重启后保持；宽限期内重启补跑一次，超时跳过，不因每轮重算未来时间而永不到期。
- [ ] AC6a：分别在领取前、领取后尚未输入、执行中、终态保存后模拟崩溃重启：未领取按宽限期处理；已领取无终态只记录一次“运行中断”且无自动输入；已有终态保持不变且不重跑。重复重启结果不变；中断后的周期任务恢复下一计划，仅一次任务停用，两者均可手动重跑且不改变自动计划。
- [ ] AC7：多个到期任务按优先级和稳定 ID 顺序执行，活动运行存在时不并发；宽限期内仅补跑当前一轮，不累计多轮，超时后正确推进下一周期。
- [ ] AC8：仅一次任务成功、失败、过期或中断后保留、自动停用并显示终态；立即重跑不启用任务、不生成 `next_run_at`，此前调度终态和实际运行仍可从历史查看。
- [ ] AC9：工作流编辑器不再显示调度字段和自动调度入口；已有 `scheduled_time`、`interval` 工作流升级后在新模块可见，已有有效调度状态保留，缺失计划时间按 R2 补齐，重复启动迁移不产生重复任务或重复执行。
- [ ] AC9a：迁移后删除任务并重启，任务不重建、不自动运行；迁移失败重试不留下部分复制或错误完成标记。已有有效计划时间原样保留并按宽限期处理；缺失计划时间只生成严格晚于迁移参考时间的下一计划。例如每天 06:00 的任务在 06:15 升级时安排次日 06:00，不补跑当天；旧任务停用状态不因迁移改变。
- [ ] AC10：脚本目标缺失时任务自动停用并显示目标缺失，不创建运行或输入；工作流引用删除保护同时由 API 校验和 SQLite 外键保证。
- [ ] AC10a：自动执行、手动重跑、成功、失败、过期和中断各生成一条持久化调度终态；重复的执行槽占用轮询不生成重复历史。REST、WebSocket 和 GUI 使用一致的任务状态与 `scheduled_task_id`，且能按独立轮次准确关联该轮的脚本步骤与重试。
- [ ] AC11：狭间启动已在四个区域或敌人选择页时直接同步并续跑；有可验证中途捷径时优先使用，均不绕回首页。
- [ ] AC12：已在首页时直接进入既有录制入口，回首页动作中没有 `to_home.bmp`、返回或 `ESC`；首页入口回放继续通过。
- [ ] AC13：确需回首页时按 `to_home.bmp` → `return.bmp` → `ESC` 顺序恢复，每次动作后验证；三类退层动作共享 6 次上限和累计 30 秒预算。重复命中按钮、混合使用三类动作、切换已知/未知画面或中途处理战斗/结算均不得重置已用预算。
- [ ] AC14：未知且无按钮时逐次 `ESC`，出现首页或“确认离开”立即停止退层；共享 6 次或 30 秒预算耗尽且仍未恢复时结构化失败，不发送第 7 次退层动作。第 6 次退层后确认首页可成功，出现退出弹窗则按既定规则额外发送一次取消 `ESC` 并验证首页，该取消不计入退层次数；收到停止信号后任何分支都不得继续输入，绝不确认退出。
- [ ] AC15：入口持续截图识别，战斗进行中零输入；识别到结束页后点击关闭并逐动作重识别，多页结算逐页处理，确认离开后再导航。启动时已在结算页不等待战斗计时；已有结算不计入本轮业务战斗次数。手动与定时启动对同一画面产生相同入口动作和结果。
- [ ] AC15a：3 分钟内持续处于战斗时不输入，超时返回“入口等待超时”；途中确认结算后执行关闭流程，不停在被动等待。等待和结算点击前均检查停止信号，停止后不再发送输入；结算后仍无法确认场景时不得视为已安全到达目标页。
- [ ] AC16：单脚本定时任务修改全局脚本配置后仍使用自身参数；工作流任务运行最新定义但运行中快照不被改写。
- [ ] AC16a：工作流“御魂 → 狭间”在第一步运行中将第二步修改为斗技、删除或重排后，本轮仍按原快照执行，下一轮读取新定义；本轮历史保留原全部步骤、顺序、参数和失败策略。提前失败或中断时仍能查看未执行步骤，但不得伪造它们的运行结果；修改原定义及后端重启后历史仍不变。
- [ ] AC17：一条任务只有一个执行时刻；同一目标的多条任务分别维护 `next_run_at`、补跑与状态。
- [ ] AC18：删除被引用工作流失败；更换或删除全部引用后删除成功，且运行历史的 `workflow_id` 既有 `ON DELETE SET NULL` 行为不变。
- [ ] AC19：调度持久化、迁移、目标缺失、单运行槽和终态均有后端回归；狭间续跑、最短路径、三段回退、未知 `ESC` 哨兵、弹窗取消、战斗零输入、结束页主动关闭及等待超时均有 Mock/回放回归。
- [ ] AC20：工作流 CRUD/步骤/失败策略/立即运行、运行历史、托盘及停止控制继续通过现有回归。
- [ ] AC21：定时任务和工作流页面在 800×600、900×650、1280×720 的真实 Electron 中无不可达操作、无横向滚动，键盘焦点与错误提示可用。

## Out of Scope

- 不新增 Windows 任务计划程序、Cron、外部调度服务、第二个计时线程或新的第三方依赖。
- 不支持月度、Cron 表达式、节假日例外或一条任务多个执行时刻；多个时刻使用多条任务。
- 不保证工作台或后端未运行时唤醒系统；只在重启后按宽限期判断是否补跑。
- 不点击“确认离开”中的确认退出操作，也不重写狭间暗域战斗、伤害阈值或已录制首页拖拽。
- 不把狭间专用的未知画面 `ESC` 兜底扩展到其他脚本或通用 `EntryPreparer`。
