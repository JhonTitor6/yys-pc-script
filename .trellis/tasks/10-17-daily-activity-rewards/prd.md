# 每日活跃度奖励独立脚本

## 目标

从庭院进入“花合战”的今日页，领取页面上已达到条件且可领取的奖励，清理确认到的奖励弹窗，再确认返回庭院。脚本不额外执行活跃任务，也不购买资源。

## 已核验素材

- 录制：`recordings/daily_activity_rewards/20261018T024329Z-2946f250`，分辨率 1136×640，3 FPS，25 帧，4 个点击事件，`completed`、零丢帧；FFprobe 元数据检查和 FFmpeg 全帧解码均通过。
- 关键画面：庭院菜单收起、菜单展开、花合战今日页的“全部领取”、领取后的“获得奖励”弹窗，以及弹窗清理后的今日页。
- 领取后画面显示“今日获得经验:36”及 20 级，证明奖励反馈已出现且弹窗随后消失；录制因紧急停止结束在花合战页，没有覆盖返回庭院。
- 录制事件只用于理解流程。运行时目标须由当前新截图中的 OCR / 图像识别确定，不能照搬事件坐标。
- 现有 `gained_reward.bmp` 与 `battle_end*.bmp` 均不匹配该“获得奖励”弹窗；实现须识别实际弹窗后复用 `YYSBaseScript` 通用结算点击回调，且不能增加战斗计数。

## 功能要求

1. 只从已识别的庭院启动；需要展开菜单时先识别对应控件，再识别并点击唯一的“花合战”菜单项。
2. 进入后必须确认“花合战”标题及“今日”页。未知页面、截图失败、页面比例不符或按钮不唯一时停止并明确失败，不发送猜测输入。
3. 将今日奖励状态分为：
   - `claimable`：今日页确认后，OCR 在领取按钮区域唯一识别到“全部”和“领取”；仅点击一次。
   - `already_claimed`：没有可领按钮，且“今日获得经验”可读并大于零。
   - `not_eligible`：没有可领按钮，且“今日获得经验”可读并为零。
   - 其余情况为 `unknown` 并停止，不能推断成功。
4. 点击后必须先识别“获得奖励”弹窗，再调用通用结算处理清理；刷新截图确认回到花合战今日页，并以按钮已消失、今日经验增加作为本次领取成功的证据。持续的重复奖励帧只允许有界清理，不得再次点击领取按钮。
5. 点击当前页面中已识别的返回控件；刷新截图并确认 `SceneManager` 识别为庭院后才正常结束。
6. 所有点击经 `GameEnvironment` / `GuardedEnvironment` 和 `RunGuard`；尊重停止、暂停和观察模式。观察模式只记录计划输入，不推进后续步骤。
7. 保持现有脚本和共享文件不变。模块公开 `DailyActivityRewardsScript`，当前不需要用户配置字段。

## 不在范围内

- 为补足条件而执行花合战任务、探索、御魂或其他日常。
- 脚本注册表、PyInstaller 清单、全局测试、父工作流接线；这些由主会话统一完成。
- 实机运行、Git 提交、推送或任务归档。

## 验收

- [ ] 从庭院仅凭当前截图识别并进入花合战今日页，非目标页面不输入。
- [ ] 三种可判定领奖状态分别输出；OCR / 页面证据不足时明确失败。
- [ ] 可领取状态最多触发一次领取；只有奖励弹窗及领取后页面反馈均确认才记录成功。
- [ ] 重复弹窗清理有上限，不会重复点领取。
- [ ] 正常结束前重新截图确认庭院；停止、观察、失败均不伪装成功。
- [ ] 夹具仅包含必要且脱敏的局部画面；原始录制保持不变。
- [ ] 运行模块离线测试、Ruff 与编译检查，并记录实机未验证边界。
