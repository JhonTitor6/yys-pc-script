# 官方一键收菜设计

## 边界与复用

- 新增 `yys/daily_collect/daily_collect_script.py` 和包导出，不改注册表、打包清单、公共脚本或父工作流。
- 继承 `YYSBaseScript` 以复用当前 `WinController`、`ImageFinder`、OCR 初始化、日志与脚本状态接口；本流程不需要 OCR、战斗结算或阵容切换，页面信号以已确认的图像模板判断。
- 未传入环境时使用 `WindowsEnvironment`，并以 `GuardedEnvironment` + `RunGuard` 限制输入、时长和未知画面；传入已包装的环境时保留其观察模式。
- 配置 schema 为空，无用户可调参数。

## 状态与动作

| 状态 | 识别条件 | 允许动作 |
|---|---|---|
| 庭院 | 公共庭院场景标记与本录制的探索灯笼同时匹配 | 点击事务入口一次 |
| 庭院事务 | 本地标题模板匹配 | 等待入口转场完成 |
| 待领取 | 标题与“一键完成”模板均匹配，且本轮尚未点击 | 点击按钮一次并设置动作已发送标记 |
| 领取处理中 | 事务页仍匹配；重复画面不清除动作标记 | 零输入等待 |
| 领取成功弹层 | 本地“领取成功”标题模板匹配 | 在确认弹层后点击录制证明的空白关闭位置一次 |
| 领取完成 | 录制证明的成功横幅出现，或“一键完成”前没有完成印章且点击后出现印章 | 设置业务结果，不再点击领取 |
| 回庭院 | 事务页成功状态和页头“庭”图标同时匹配后点击一次 | 等待新的庭院截图 |
| 完成 | 公共庭院标记和探索灯笼同时匹配 | 设置 `flow_complete=True` 并正常返回 |

初始未知页、未确认按钮、领取后缺少完成信号、返回后缺少庭院信号、超时或保险丝停止均失败退出。观察模式只记录第一个已识别动作，随后以非完成结果结束，不继续推进依赖真实输入的转场。

## 识别与坐标

- 图像模板取自指定录制。运行截图归一到录制客户区 1136×640；发送输入时按真实截图尺寸换算回客户区坐标。
- 模板在实际生产匹配器中对脱敏真实帧做正、负样本验证。庭院状态要求公共场景标记与本地探索灯笼同时命中；事务入口模板只在已识别的庭院页使用，避免把可能消失的入口图标当成结束页标记。
- 成功弹层的关闭点以弹层标题匹配位置加录制验证偏移计算，并验证坐标仍在客户区内；未知页或缺失成功标题时不触发该点击。
- 每次等待都重新截图。点击后只等待和判定，不重试同一点击；每个确认页面最多输入一次。
- 若一键领取前页面已有完成印章，因缺少“启动时已完成”录制，脚本失败退出且不点击；点击后的完成印章才可作为本轮结果证据。

## 数据流

`GameEnvironment.capture_screen()` → 真实客户区 BGR 帧 → 生产模板识别 → 当前状态允许的单次动作 → 新鲜帧验证下一状态。输入统一经 `GuardedEnvironment`，观察模式不触达底层环境。

## 兼容与风险

- `DailyCollectScript` 暴露给未来注册项的唯一类；不更改既有脚本及其行为。
- 录制只证明“有任务可领取”的成功路径；没有“启动时已全部完成”样本。因此该初始分支不作为成功跳过条件，需后续提供真实样本后再扩展。
- 不确定“领取成功”弹层关闭或庭院返回时，脚本抛错而不继续；这可能使已领取但未关闭的任务报告失败，优先避免误报成功和重复点击。
