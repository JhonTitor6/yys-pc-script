# 官方一键收菜单独脚本

## 目标

新增可独立运行的官方“庭院事务 → 一键完成”脚本。只领取该入口能一次完成的任务奖励，不逐项执行每日玩法。只有验证领取结果并确认返回庭院后，脚本才正常结束。

- `recording.mp4` 为 1136×640、43 帧，完整解码成功。结尾帧显示已回庭院；点击后的第一帧处于淡入过渡，不能当作结束页证据。
- 事件顺序：庭院打开“庭院事务”；点击“一键完成”；出现“领取成功”弹层；关闭弹层后任务列表出现完成标记；点击页头“庭”按钮；视频末段稳定显示庭院。
- 录制中的第四次点击没有证明新的业务动作，脚本不照搬。`庭`按钮在页面已识别后关闭面板并返回庭院。
- 当前录制未覆盖“启动时已经完成”的独立初始状态；实现不得据此推断并跳过待领取任务。未知、失败、超时和停止均不能作为成功返回。

## 范围与约束

- 只在识别到庭院后，进入官方庭院事务面板并点击已识别的一键完成按钮一次。
- 识别“领取成功”弹层；仅在弹层识别后关闭它，再验证成功提示／已完成标记。
- 通过已识别的页头“庭”按钮回庭院，并用庭院场景标记确认结束。
- 所有截图必须新鲜；输入只经 `GameEnvironment` 和 `RunGuard`；支持调用方注入观察模式环境和停止信号。
- 不增加配置项；脚本 ID `daily_collect` 及注册、打包、父工作流接线由主会话处理。
- 不操作真实游戏，不改原始录制，不提交、不推送、不归档。

## 验收标准

- [ ] `DailyCollectScript` 可从 `yys.daily_collect` 导入，且声明“日常”脚本元数据。
- [ ] 庭院、事务面板、一键完成按钮、领取成功弹层、完成标记和回庭院均由实际图像识别确认；未知状态不输入。
- [ ] 一键完成最多点击一次；重复画面只等待，不重复消耗或执行。
- [ ] 正常返回前，必须先验证领取结果，再重新截图确认庭院。
- [ ] 停止、观察模式、识别失败和超时不会设置 `flow_complete`，也不会被当作正常业务完成。
- [ ] 离线测试使用最小脱敏真实帧，覆盖完整流程、重复帧、未知入口、未出现成功信号、停止与观察模式。
- [ ] Ruff 和 Python 编译检查通过；不改共享注册、打包及父工作流文件。
