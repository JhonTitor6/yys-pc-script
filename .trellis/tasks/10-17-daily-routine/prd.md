# 每日一条龙：收菜、寄养、逢魔、地域鬼王、御魂与活跃奖励

## 目标

用户启动一次，按顺序完成收菜、结界寄养、逢魔、地域鬼王、御魂和每日活跃度奖励领取，减少日常任务之间的人工切换。

2026-10-17 用户已同意创建 Trellis 任务并进入规划；尚未批准实施，尚未授权实机游戏操作。

2026-10-17 后续授权更新：用户要求先提交全部工作区待提交内容，再按每个独立流程建立独立脚本任务，最后通过工作流串联；用户明确要求基于已录制的两个流程开始实施。本次授权包含保存现有改动的 Git 提交，不包含实机自动执行、推送和任务归档。

## 已确认事实

- 用户要求的顺序：①收菜，使用官方一键完成任务按钮；②结界寄养；③打逢魔；④地域鬼王；⑤御魂；⑥领取每日活跃度奖励。
- 用户明确纠正：逢魔不是狭间暗域，两者必须独立识别、规划和实现；不得借用狭间暗域的开放时段或业务流程作为逢魔依据。
- 用户采用录制、由助手提取流程的方式；逢魔内部操作范围以录制及必要的用户说明为依据，不默认采用此前提出的 A／B 方案；助手不自行启动录制或发送游戏输入。
- `ui_backend/scheduler/service.py:35` 的 `run_workflow_now` 已支持顺序执行；`_run_step_with_policy` 等待运行结束后处理失败策略。已有编排能力不等于六个业务步骤均已实现。
- `ui_backend/scripts/default_registry.py` 已登记御魂和地域鬼王。对业务代码及现有任务、文档的初步检索未找到收菜、寄养、逢魔、活跃度领奖的对应完整实现。
- `yys/regional_demon_boss/regional_demon_boss_script.py:63` 和 `.trellis/tasks/09-07-regional-demon-boss/prd.md` 表明：现有地域鬼王脚本固定挑战丹霞山／山童一次，使用已有难度；不支持多目标轮巡。
- 项目根 `AGENTS.md` 要求御魂重新启用 `entry_spec` 前以真实帧或回放验证战斗、结算至组队页的识别；不能直接假定它已支持任意页面无人值守进入。
- 工作区已有其他任务的大量未提交修改，本任务不得覆盖或混入这些修改。

## 需求

- R1：按用户给出的六步顺序执行；各步骤的内部范围按后续确认结果细化。
- R2：收菜以官方一键完成任务功能为范围起点，不擅自扩大为逐项手动完成所有日常。
- R3：完成当前步骤的业务结果和页面状态确认后，才能进入下一步；不能仅凭线程退出、按钮已点击或等待时长判定成功。
- R4：运行结果须区分完成、已完成而跳过、未满足条件、失败和用户停止；具体继续／中断策略待用户确认。
- R5：保留现有单独运行脚本的行为；只为串联补齐必要能力。
- R6：页面或目标无法确认时，不以固定坐标盲点；用户停止后不再进入后续步骤。
- R7：使用后续录制提取入口、关键画面、操作顺序、完成状态和返回路径；录制未覆盖的分支明确保留为待确认，不将坐标和等待时长直接照搬为业务完成规则。

## 验收标准草案

- [ ] AC1 → R1：完整回放按六步顺序推进，任何一步不会提前启动下一步。
- [ ] AC2 → R2：收菜只触发已识别的官方按钮，并验证结果；不能把其他入口当作一键完成按钮。
- [ ] AC3 → R3：每步验证完成状态，清理结算／奖励遮罩，并确认下一个入口；未知状态不误报成功。
- [ ] AC4 → R4：已完成、条件不足、失败、用户停止分别产生可辨认结果，并遵循最终确认的策略。
- [ ] AC5 → R5：现有单独御魂运行次数、停止行为不变；地域鬼王保持指定目标单次挑战、准备／战斗阶段零输入、重复结算不重复计数。
- [ ] AC6 → R6：停止后不推进下一步；未知页面、错误目标、入口失败不会触发盲点。
- [ ] AC7：覆盖一条龙正常串联与中途停止的离线验证；实机验证若未做，明确记录，不把离线通过描述为实机通过。
- [ ] AC8 → R7：逢魔需求和识别依据可追溯到逢魔自身录制；记录未覆盖分支，不以狭间暗域素材替代逢魔证据。

## 暂不纳入范围

- 多账号轮换、后台重复执行、自动购买资源；用户尚未提出这些能力。
- 提交或归档现有任务、修改无关代码、安装新依赖。
