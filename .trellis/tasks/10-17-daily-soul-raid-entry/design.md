# 单人魂土设计与证据边界

## 契约

- 独立包 `yys/soul_soil/` 导出 `SoulSoilScript`；ID `soul_soil`。`SCRIPT_META` 和反射 schema 包含 `max_battle_count=10`、`lineup_group="御魂"`、`lineup_name="魂土"`。
- 不修改 `yys/soul_raid/`。`soul_team` 只代表旧组队入口，不可作为单人魂土就绪证据。
- 所有输入走 `GameEnvironment` 与 `GuardedEnvironment`；脚本检查停止/暂停及 RunGuard。观察模式不发真实输入，也不把未执行流程记为完成。
- 每次识别都取新截图。未知画面零输入并以明确错误退出。

## 流程

1. 只有确认庭院后用 `LineupSwitcher` 应用 `("御魂", "魂土")`。用户确认只有首行名为魂土；排除底部被遮挡的名称，完整可操作行按全名唯一匹配，真正重名仍失败。成功后用 `return.bmp` 返回并重新验证庭院。
2. 在庭院识别 `home_to_exploration.bmp`，确认探索地图后识别并点击 `exploration_to_soul.bmp`。
3. 在“御魂”四个模式卡片页用录制提取的八岐大蛇卡片模板定位目标卡；模板中心对应录制实际点击位置。等待悲鸣关卡页，用 OCR 定位“悲鸣”并以该标签亮度确认是否已选中，未选中时才点击。
4. 仅在该关卡页确认“组队”与“挑战”两个独立按钮后，点击 OCR 识别到的“挑战”。这条入口选择单人；不触发“组队”。
5. 在单人准备页打开“预设”，OCR 选择“御魂”分组；新截图须显示队伍列表，并确认首个高亮行是“魂土”后点“出战”。重新识别“准备”按钮才开始战斗。
6. 战斗过程中零输入。用 YYS 通用战斗结束模板和结算回调处理胜负、继续/领奖；每场结算最多增加一次总次数。达到目标次数立即停止发起后续挑战。
7. 结算遮罩消失后识别既有 `to_home.bmp`，点击并重新截图确认 `home`；若出现“确认离开”弹窗，只发送 `ESC` 取消，再识别 `home`。为确保每次都从已知入口继续，未完成次数时也先回庭院，再重复步骤 2–7。

## 录制证据与边界

- 视频 `recordings/soul_soil/20261018T024218Z-0f618f91/recording.mp4`：1136×640，3 FPS，声明并完整解码 163 帧；21 个鼠标事件对应 42 张有效截图，丢帧为 0。
- 录制证明：庭院、探索地图、御魂模式卡片、悲鸣选层、挑战/组队按钮并列的关卡页、单人准备页、御魂组与首个魂土队伍预设、出战/准备按钮、一场战斗及奖励弹窗。
- 式神录与 Lobby 各自存在队伍预设面板：前者使用 `LineupSwitcher` 应用，后者按录制确认首个高亮“魂土”并点“出战”。两处操作均保留，不以其中一处取代另一处。
- 录制以 `发现宝藏` 弹窗结束，文件 `status=completed`、`stop_reason=emergency_stop`。没有返回庭院或第二场的证据；这些通过离线状态流模拟，真实运行边界仍未验证。
- 生产图像只提取八岐大蛇模式卡、关卡标题、准备按钮、预设行高亮和宝藏标题；悲鸣选中态由 OCR 标签位置和亮度确认。脱敏夹具模糊账户昵称和队伍立绘，只保留页面文字与识别控件。原始 `recordings/` 不改动。

## 兼容与接线

- 本任务只拥有任务文档、`yys/soul_soil/` 和 `tests/fixtures/soul_soil/`。
- `ui_backend/scripts/default_registry.py`、`build_backend.spec`、共享 `yys/common/`、全局 `tests/` 和父工作流由主会话统一接线。
- 不创建第二套通用结算、场景图或阵容切换器；Lobby 中读取队伍预设是录制证明的另一处 UI 操作，不替代庭院里的 `LineupSwitcher`。
