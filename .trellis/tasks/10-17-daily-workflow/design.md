# 工作流串联设计

- 复用 `SchedulerService` 与既有工作流 JSON，不新增调度器、数据库表、UI 类型或第二套业务脚本。
- 首步前校验生产 RunManager 的全部业务脚本已登记且类能导入，执行器具备 wait 和 run_status；测试替身未提供注册表时保持既有轻量接口。
- 内部启动步骤返回运行 ID 及是否实际由本次调度器调用按时停止；公开 `run_step` 保持原有返回值。该布尔值只描述 `run_until_time` 本次停止，不推测用户停止原因。
- 等待返回未完成、状态缺失或非终态时明确失败；普通用户停止中断后续步骤，不受失败重试／继续策略覆盖。
- 已有 manual 中断、error 策略和 wait_duration 行为保持。skipped 发布 skipped，保留未全部成功的结果。
- 新增六步 JSON 草案供审阅及后续接入现有工作流编辑器，默认 disabled/manual，不写入用户数据库、不启动游戏。单人魂土步骤默认次数 10；缺失脚本通过预检查阻断，不能生成总成功。
- 实际六步联调依赖收菜、寄养、逢魔、地域鬼王、单人魂土和活跃领奖脚本及各自页面衔接通过验收。
