# 逢魔独立脚本

## 目标

将逢魔做成独立脚本，使用录制中的入口和既有通用战斗结算能力，完成后确认返回庭院；始终区分探索、集结和全流程完成。

## 需求

- 独立逢魔脚本，明确区别于狭间暗域；用户已要求开始实施。
- 素材 `recordings/fengmo/20261017T133046Z-a4cc53f5.partial`：75 帧可解码、15 个操作，覆盖庭院、逢魔预设应用、日常入口、逢魔探索和进入集结。
- 复用既有 `LineupSwitcher`，分组／阵容以录制可读文字为准；未知切换结果不重试。
- 2026-10-17 用户明确确认：使用“逢魔”分组中的“通用”阵容，与逐帧核验和当前默认配置一致；下方另一阵容为“周一”，不得混读分组与阵容名称。先前基于缩略图提出的预设选择问题已关闭。
- 按已录流程识别入口和探索结果；发现的首领必须通过本录制详情验证，不能点击其他活动目标。
- 用户后续明确：结算、领奖复用现有处理；返回庭院先点击返回按钮，再点击 `to_home`。不再因缺少这些步骤的新录制而在集结页人为阻断。
- 等待集结和战斗时持续截图、零输入；只在通用结算／奖励识别后调用既有处理，一场战斗不重复计数。
- 清理结算后重新识别返回按钮，点击后重新截图识别 `to_home`，点击后确认庭院；少任何一个必要状态都不能报告完成。
- 录制出现共享阵容确认的新文案“即将更换式神…的预设御魂”，需要兼容；旧行为原子保持：分组名称只在分组区、阵容名称只在所选分组内精确匹配，同行应用按钮与成功提示均必须验证；已有弹窗拒绝，旧成功提示拒绝，单条契灵提示不算成功，未知结果不重复应用。

## 验收标准

- [ ] 作为独立实验脚本登记，可单独观察运行。
- [ ] 本录制覆盖的入口、探索及首领详情按实时画面识别推进，不按录制时间线盲点。
- [ ] 不调用狭间暗域业务，不接受狭间页面作为逢魔状态。
- [ ] 集结后等待战斗结束，复用通用结算和奖励处理；重复结算帧仍只计一次战斗，未见结算不能提前离开集结。
- [ ] 同屏同时存在两个导航按钮时，先返回，再在新截图中识别并点击 `to_home`；只有庭院已确认才公开 `flow_complete=true`。
- [ ] 停止及观察模式不产生真实输入；真实帧离线测试能验证页面边界。
- [ ] 新文案只在本次点击应用后接受完整首尾文本与明确确定按钮，仍等待装备御魂成功；旧阵容测试全部保持通过，参数影响范围不变。
