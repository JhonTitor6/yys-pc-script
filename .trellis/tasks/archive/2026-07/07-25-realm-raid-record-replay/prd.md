# 录制回放框架与自动结界突破

## Goal

建立一套可重复使用的“真实流程采集 → 离线场景回放 → Agent 自动调试 → 少量真机校准”闭环，
优先补全并验证结界突破完整自动化流程，后续可复用于狭间暗域、御魂、御灵和探索等副本。

## Background

- 当前项目已采用事件驱动脚本架构，并通过图像匹配、OCR 和后台鼠标键盘操作驱动游戏。
- `RealmRaidScript` 已存在，具备结界突破的基础事件处理逻辑，但缺少覆盖完整流程和异常分支的可复现回归数据。
- 当前脚本按固定 3×3 区域扫描可攻击目标，扫描顺序为从上到下、每行从左到右；未实现战力 OCR 或目标优先级排序。
- 当前“首次退三次”通过“页面仍有 9 个可攻击目标”判断第一次挑战，并在点击进攻后执行
  `ESC → ENTER → 再次挑战` 三轮；该行为尚无结界突破专属流程测试。
- 当前没有 `yys/realm_raid/test_*.py`，相关测试仅覆盖默认配置注入和入口场景声明。
- 项目已有 `GameEnvironment`、`MockEnvironment`、`ActionLog`、`ScenarioRecorder` 和
  `SceneReplayEnvironment` 等测试基础设施。
- 现有 `ScenarioRecorder` 主要保存单张截图和动作 JSON，尚不能直接把连续录屏转换成多场景、
  有时序关系、可断言的完整回放用例。
- 当前 `yys/realm_raid/realm_raid_script.py` 有用户保留的未提交修改：
  `BATTLE_END_CLICK_SLEEP` 从 2 秒调整为 3 秒，实施时不得覆盖。

## Requirements

### R1. 通用流程采集

- 第一版提供独立命令行入口，例如
  `python tools/record_gameplay.py --scenario realm_raid`；桌面界面集成不属于第一阶段。
- 第一版采用项目内伴随录制器，不以普通 MP4 作为唯一输入。
- 采集阴阳师游戏窗口的连续画面、窗口客户区尺寸、时间戳以及用户鼠标/键盘操作。
- 所有坐标应以游戏客户区为基准，避免窗口移动导致回放数据失效。
- 同一次采集应同步输出可观看的视频和机器可读的事件/元数据。
- 录制结果应采用可检查、可版本管理或可按需忽略的明确目录结构。
- 原始视频、完整帧、输入事件和派生缓存默认保存在本机 `recordings/`，并通过 `.gitignore` 排除。
- 提供按单次录制删除原始数据及派生缓存的清理命令。
- 采集必须提供显式开始、停止和异常中止机制，不得失控记录用户的无关桌面操作。

### R2. 场景数据集生成

- 从一次完整流程采集中提取关键帧，并关联触发动作、动作前状态和预期动作后状态。
- 支持人工修正场景名称、裁剪识别区域和敏感画面删除。
- 只有经过筛选、裁剪并由用户确认的最小关键帧、模板图和场景配置可以进入 Git。
- 生成的数据能够被现有或扩展后的 `SceneReplayEnvironment` 读取。
- 第一版不要求仅凭视觉模型全自动正确标注所有场景；允许 Agent 生成候选结果后由用户确认。

### R2.1 第一阶段录制集

- 第一条主流程录制从庭院开始，进入结界突破，完成本组首次退出三次，并至少正常打完两个目标。
- 第二条组末流程录制覆盖最后一个可攻击目标结束、自动换组以及新九宫格出现；若游戏版本
  实际出现刷新确认，则将该确认作为兼容分支补录。
- 券不足、战斗失败和异常弹窗采用遇到时补录的短流程，不阻塞伴随录制器和主流程首版交付。
- 未取得真实异常录制前，相关状态应保留安全停止或可注入测试接口，不得通过猜测画面进行真机点击。

### R3. 离线自动调试

- Agent 能在不打开游戏窗口的情况下运行结界突破完整流程回放。
- Agent 可以不限次数自动执行离线回放、分析失败证据并迭代代码。
- 回放应记录脚本实际动作，并能断言动作类型、坐标范围、顺序、场景转换和停止原因。
- 随机等待和随机坐标偏移在测试环境中必须可控，避免不稳定测试。

### R4. 自动结界突破

- 支持从庭院场景启动，经探索地图自动进入结界突破；如果启动时已在结界突破页，则直接开始。
- 入口跳转复用现有 `home → exploration → barrier_breakthrough` 场景资产，并补充基于真实图片的链路回放测试。
- 进入结界突破后完成可攻击目标选择、挑战、战斗结束和继续下一目标的主流程。
- 第一版按固定九宫格顺序选择目标：从上到下、每行从左到右；不增加战力 OCR、阵容识别或弱目标优先策略。
- 应跳过已击破或不可攻击目标；同一轮内每个可攻击目标至多被选择一次，自动换组或手动刷新后
  开始新一轮。
- 支持配置中的退出三次策略：每组新九宫格仅在第一个目标上退出三次，刷新出的下一组九宫格重新执行一次。
- 是否已执行退出三次必须由显式的每轮状态维护，不再仅依赖“当前识别到 9 个可攻击目标”推断。
- 对胜利、失败、刷新/无可攻击目标、挑战券不足、常见遮挡弹窗和无法识别场景提供明确处理。
- 连续异常或超时后安全停止并输出可诊断信息，不得无限点击。
- 保留现有脚本配置、事件驱动基类和用户未提交的 3 秒等待调整。

### R5. 安全控制

- 真机调试默认采用有限动作次数、单次运行超时和紧急停止机制。
- 支持只识别不点击的观察模式，便于在真实游戏上验证识别结果。
- 默认每次真机试跑由用户手动开始；当用户在当前活动任务中明确要求 Agent
  “自行调试”时，允许 Agent 通过显式确认短语启动独立的受控单次试跑。
- Agent 授权路径不得取消动作、超时、未知场景或 `F12` 保险丝，也不得在同一进程内自动重启；
  每次重试仍必须是新的单次 CLI 调用。
- 单次真机试跑默认上限为 3 分钟或 30 个输入动作，任一条件先达到即停止。
- 连续 3 次无法识别当前画面时立即停止。
- 提供全局 `F12` 紧急停止键；停止路径应优先于普通业务动作。
- 采集与运行日志不得默认保存完整桌面或与目标游戏无关的输入。

### R6. 后续复用

- 采集、场景描述、回放和断言能力不得与结界突破业务逻辑硬编码耦合。
- 后续副本接入应主要新增各自的场景资产、转换描述和业务测试，而不是复制录制框架。

## Acceptance Criteria

- [x] 能完成主流程和组末刷新两条结界突破真实流程采集，并分别产出视频/关键帧、窗口元数据和输入动作记录。
- [x] 能将该采集转换为至少一条可重复运行的结界突破场景回放测试。
- [x] 从庭院开始的离线场景回放能够自动进入结界突破；从结界突破页开始时不会执行多余入口点击。
- [x] 离线回放能验证从入口到至少一次挑战结束并选择下一目标的完整主路径。
- [x] 每组九宫格首次退出三次策略有独立回归测试，次数和后续正常挑战行为正确。
- [x] 同一组九宫格不会重复执行退出三次；自动换组后的新九宫格会重新执行一次。
- [x] 至少覆盖胜利、失败、无可攻击目标或刷新、挑战券不足、未知场景超时五类分支。
- [x] 离线测试不依赖真实游戏窗口，重复运行结果稳定。
- [x] 真机观察模式不会发送鼠标键盘操作。
- [x] 真机执行达到 3 分钟、30 个输入动作、连续 3 次未知画面或 `F12` 紧急停止中的任一条件时能够停止。
- [x] 一次真机试跑结束后不会自动发起下一次试跑。
- [x] 现有公共测试以及结界突破相关测试通过。
- [x] 录制/回放接口能由另一个副本以新增数据和少量适配代码复用。

## Out of Scope

- 第一阶段不同时补全狭间暗域、御魂、御灵和探索的所有业务流程。
- 第一阶段不在现有桌面界面中增加录制管理页面或按钮。
- 不承诺只依靠单个 MP4、完全无人确认即可生成生产可用脚本。
- 不构建绕过游戏安全机制、反作弊检测或服务条款限制的能力。
- 不允许 Agent 在没有动作上限、超时和人工中止能力的情况下长期无人值守真机试错。
