# 修复斗技结算漏记场次

## Goal

修复斗技胜利结算可以正常点击、但没有增加总战斗次数和输出完成日志的问题。

## Background

- 2026-08-29 19:00 后日志显示脚本持续进入新战斗，但没有任何“战斗完成”日志。
- `_on_battle_end()` 只要执行就必然增加总场次并记录日志，因此实际点击来自不记录总场次的 `_on_battle_victory()`。
- 斗技胜利画面可同时命中优先注册的公共胜利模板与后注册的斗技结束模板；事件循环每帧只处理首个匹配，点击后后续模板不保证再次出现。
- 上次修复只去重胜利次数，仍隐含依赖“胜利回调之后一定触发结束回调”的错误假设。

## Requirements

- 首个胜利终态必须同时记录一场总战斗、一次胜利和一条完成日志。
- 首个失败终态必须记录一场总战斗、不增加胜利次数并记录一条完成日志。
- 同一场的其他重复或不同结算模板仍正常点击，但不得重复计数或打日志。
- 下一场“切换自动战斗”入口出现后，允许再次消费一个胜负终态。

## Acceptance Criteria

- [x] 连续两次胜利回调只得到总场次 1、胜利 1、日志 1 条，同时执行两次点击。
- [x] 同场随后触发普通结束回调时不再增加计数或日志。
- [x] 下一场“切换自动战斗”入口后，失败回调得到总场次 2、胜利仍为 1、日志共 2 条。
- [x] 斗技与公共战斗计数回归测试通过，`git diff --check` 通过。
- [x] 不改动用户已有的 `gui/installer.nsh` 工作区变更。

## Out of Scope

- 不推算或修正已产生的历史日志。
- 不重构全局事件分发器或其他脚本的结算流程。

## Notes

- 本任务为斗技单模块状态修复，采用 PRD-only 轻量流程。
